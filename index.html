LLM tokens/s calculator

Pick a model and your hardware to estimate local generation speed (llama.cpp-style, memory-bound).

Model

Dense part = attention, embeddings, shared experts, router. For a dense model: total = active = dense. The rest is treated as routed experts.

MTP (drafter, speculative decoding)

The drafter reads its own weights for each proposed token, and the main model verifies the k tokens in one pass. α is not published: 0.6–0.8 is a plausible range, to be measured. Gemma 4 drafter sizes are estimates (not published); for other models, fill them in.

Context

Speed drops as the context fills up. The filled part is also used as the prompt length for the prompt-processing time.

Hardware

GPUs

Effective PCIe link = min(GPU gen, slot gen) × min(GPU lanes, slot lanes). E.g. a mechanical x16 slot wired x4 through the chipset → set x4.

System RAM / CPU

Consumer desktops have 2 channels, however many DIMMs are installed (4 DIMMs ≠ 4 channels). Threadripper/EPYC/Xeon: 4 to 12.

CPU GFLOPS: ~300–1500 for a recent desktop with AVX2/AVX-512.

Unified memory (Apple Silicon / iGPU)

CPU and GPU share the same memory: no PCIe and no copies between them. Default macOS GPU limit: ~2/3 of RAM (≤ 36 GB) or ~3/4 (above), can be raised with sudo sysctl iogpu.wired_limit_mb. Beyond that, the model overflows to disk (mmap).

Bandwidth: official Apple figures (2nd-generation Pro/Max chips and M5 Pro/Max verified; the rest and GPU compute are approximate, notably M5 base, Pro and Max). Mini PC: bandwidth = 2 channels × 8 B × 6400 MT/s ≈ 102 GB/s, the iGPU reads the same RAM as the CPU; set memory and GPU limit to what Windows actually gives the iGPU.

Strategy & efficiencies

Typical values: GPU 0.7–0.85 (CUDA), 0.5–0.7 (Vulkan); RAM 0.6–0.75. Latency per transfer covers sync + kernel launches (often 20–80 µs).

Method

Formulas used
  • Size: weights (GB) = parameters (B) × bpw / 8. KV (GB) = 2 × KV heads × head dim × layers × context × bytes/element; for sliding-window layers (SWA), context is replaced by min(context, window). Re-read per token: only the useful part of the KV (filled, or inside the window). Layers that share the KV of an earlier layer (Gemma 3n/4 E2B/E4B) are counted once.
  • Active expert fraction f = (active − dense) / (total − dense).
  • Placement: greedy fill of the GPUs (capacity = VRAM − reserve), then RAM, then disk (mmap). In MoE mode, attention + KV go first, experts afterwards.
  • Generation: for each device, bytes read/token = dense + experts × f + KV × (filled/allocated); time = bytes / (bandwidth × efficiency). On CPU: max(memory time, 2 × active params / GFLOPS). Devices run one after another (layer split), so times add up.
  • Transfers: each hop from one device to another costs latency + hidden × 4 B / PCIe throughput. In MoE mode, a layer whose experts live elsewhere than its attention costs 2 transfers.
  • Prompt processing: GPUs are compute-bound (2 × active params × token). Weights in RAM are either processed by the CPU or streamed over PCIe to the main GPU (first in the list) for every ubatch, like llama.cpp — the faster of the two is kept. This is where PCIe matters most.
  • Quantization: only formats at or below the precision the model was released in are offered (e.g. a model published in 8-bit gains nothing from an F16 conversion).

This is a theoretical ceiling: real numbers are typically 10–30% lower depending on the backend, quantized kernels and system load.
